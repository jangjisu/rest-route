# Rest Stop Maintainability Improvements Plan

**Goal:** 주유 가격 동기화에서 연결 상태의 단일 기준을 확립하고, 경로 조회의 중복 DB 조회를 제거하며, 비대해진 지도 메인 JavaScript의 렌더링 책임을 분리한다.

**Architecture:** `rest_oil`을 휴게소-주유소 연결 및 관리자 잠금 상태의 기준 데이터로 유지하고 `rest_oil_price`는 외부 가격 응답과 파생 연결 값만 보관한다. 경로 조회는 요청 초기에 읽은 `RestStopEntity`를 전체 대안 경로의 집계에도 재사용한다. 프론트는 `rest-stops-map.js`를 지도·요청·화면 상태를 조율하는 진입점으로 남기고 상세 View와 경로 결과 View를 별도 ES 모듈로 분리한다.

**Tech Stack:** Java 25, Spring Boot 3.5, Spring Data JPA, MySQL/H2, JavaScript ES modules, Node test runner

## 작업 항목과 진행 순서

### 1. 주유 가격 전체 동기화 개선

- `rest_oil`을 휴게소 연결과 `adminOverridden` 상태의 단일 기준으로 사용한다.
- `RestOilPriceEntity`와 가격 조회 조건에서 `adminOverridden` 의존을 제거한다.
- 전체 페이지 조회 성공 시 현재처럼 `rest_oil_price`를 전체 삭제 후 새 응답으로 교체해, 외부 응답에서 사라진 가격 정보도 서비스에서 제거한다.
- 새 가격 행을 저장한 뒤 같은 트랜잭션 안에서 `rest_oil.standard_rest_code`와 `rest_oil.rest_stop_service_area_code`를 기준으로 가격 행의 파생 연결 값을 다시 채운다.
- 부분 페이지 성공 시 기존 가격 행은 upsert하고, 새로 생긴 행도 동일한 기준으로 매핑되도록 backfill을 실행한다.
- 관리자 연결·해제·자동 매칭 복귀 동작은 `rest_oil` 전체 행을 기준으로 유지하고, 가격 행은 즉시 화면에 반영할 파생 연결 값만 함께 갱신한다.
- 관리자 응답의 `adminOverridden` 필드 형식은 유지하되 값은 같은 물리적 주유소의 `rest_oil` 상태에서 계산한다.
- `DATA.md`, `API.md`, `ARCHITECTURE.md`에서 두 테이블이 잠금 상태를 중복 소유한다고 적힌 내용을 단일 기준 구조로 수정한다.
- 현재 프로젝트는 Hibernate `ddl-auto=update`를 사용해 삭제된 엔티티 필드의 실제 DB 컬럼을 자동 제거하지 않는다. 코드 매핑 제거와 별도로 운영 DB의 `rest_oil_price.admin_overridden` 물리 컬럼 제거용 일회성 DDL을 문서에 명시한다.

### 2. 경로 조회 중복 제거

- 모든 대안 경로에서 경로상 휴게소 후보를 먼저 계산하고 서비스 영역 코드를 합친다.
- 요청 초기에 이미 조회한 `allRestStops`에서 필요한 엔티티를 선별해 집계 서비스에 전달한다.
- `RestStopAggregateQueryService`에 미리 조회한 `RestStopEntity`를 받는 진입점을 추가하고, 기존 코드 목록 기반 진입점은 이 메서드에 위임한다.
- 이미지·EV·테마·이벤트·상세/주유/먹거리 집계는 경로마다 반복하지 않고 전체 후보 집합에 대해 한 번 조회한 뒤 경로별 응답 조립에서 재사용한다.
- 경로 순서, 방향 필터, 추천 기준과 응답 JSON은 변경하지 않는다.

### 3. 프론트 메인 파일 역할 분리

- 화면 전체 재설계가 아닌 내부 모듈 분리이며, 현재 UI·동작·DOM 계약을 유지한다.
- `rest-stop-detail-view.js`로 상세 상태, 주차·편의시설·먹거리·주유·테마·이벤트·EV 등 상세 표시 책임을 이동한다.
- `route-rest-stop-view.js`로 경로 선택 카드, 전국 평균 유가, 필터·건수, 경로상 휴게소 카드와 표시용 포맷 책임을 이동한다.
- `rest-stops-map.js`에는 초기화, 지도 SDK/마커, 사용자 입력, 요청 호출, 현재 선택 상태와 두 View 사이의 조율을 남긴다.
- View 모듈은 필요한 DOM과 콜백을 인자로 받아 메인 모듈의 가변 전역 상태를 역참조하지 않도록 한다.
- 기존 `rest-stops-map.test.js`의 테스트를 역할별 테스트 파일로 이동하고, 메인에는 조율 동작 테스트만 남긴다.

## 대안과 Trade-off

### 주유 가격 연결 상태

- 별도 매핑 테이블을 만들면 가격·편의시설 테이블과 독립적인 모델이 되지만, 현재 관리 대상과 사용처에 비해 스키마와 관리 API가 과도하게 커진다.
- 두 테이블의 잠금 상태를 계속 복제하면 조회는 단순하지만 전체 교체 동기화 때 상태를 함께 복구해야 하고 불일치 가능성이 계속 남는다.
- 따라서 관리자 매핑이 이미 보존되는 `rest_oil`을 기준으로 두고 가격 연결을 파생시키는 방식을 선택한다.

### 경로 집계

- 요청 범위 캐시나 전역 캐시를 추가할 수도 있지만 수명주기와 무효화 책임이 늘어난다.
- 이미 같은 요청 안에 존재하는 엔티티 목록과 집계 결과 Map을 지역 변수로 재사용해 추가 상태 없이 중복만 제거한다.

### 프론트 모듈 분리

- 포맷 함수만 이동하면 안전하지만 메인 파일의 DOM 렌더링 책임이 남아 분리 효과가 작다.
- 검색·지도·모달 Controller까지 전면 분리하면 공유 상태와 이벤트 흐름을 크게 바꿔 회귀 위험이 높다.
- 상세 View와 경로 결과 View를 먼저 분리해 의미 있는 크기 감소를 얻고 지도·상태 조율은 안정적으로 보존한다.

## 테스트 계획

1. 전체 가격 동기화가 기존 행을 교체하고 `rest_oil` 기준 연결을 같은 트랜잭션에서 복구하는 실패 테스트를 먼저 작성한다.
2. 부분 동기화의 신규 가격 행도 연결되며 관리자 잠금 상태를 가격 엔티티에 복제하지 않는 테스트를 작성한다.
3. 관리자 연결·해제·잠금 해제 응답이 `rest_oil` 기준 상태를 반환하는 테스트를 보강한다.
4. 경로가 여러 개여도 `rest_stop`과 관련 집계 조회가 후보 전체에 대해 한 번만 수행되는 서비스 테스트를 작성한다.
5. 추출한 두 프론트 View의 포맷·필터·DOM 출력 테스트를 역할별 파일에서 유지하고 메인 초기화 회귀를 확인한다.
6. 집중 테스트 후 Java/JS 전체 테스트, 정적 분석과 커버리지 게이트를 실행한다.

## 스펙 영향도

- 스펙 변경 없음 판단 이유: 동기화 내부 저장 책임, 조회 재사용과 프론트 모듈 경계만 변경하며 공개 endpoint, 요청·응답 필드, 상태 코드와 외부 API 호출 계약을 그대로 유지하기 때문이다.
- 내부 API: endpoint, request, response 필드와 오류 계약은 변경하지 않는다. 관리자 응답의 `adminOverridden` 값의 출처만 가격 행에서 기준 `rest_oil` 행으로 바뀐다.
- 외부 API: 호출 endpoint, 페이지 처리와 응답 VO는 변경하지 않는다.
- 데이터: `rest_oil_price.admin_overridden` 소유권과 엔티티 매핑을 제거하고 `rest_oil_price.rest_stop_service_area_code`를 `rest_oil`에서 파생한다. 운영 DB 물리 컬럼 제거는 일회성 DDL이 필요하다.
- 제품/UI: 사용자에게 보이는 화면과 기능은 변경하지 않는다.
- 아키텍처: 경로 집계가 기존 조회 결과를 받는 진입점을 추가하고, 지도 메인 파일의 두 렌더링 책임을 별도 View 모듈로 이동한다.
- 품질: 기존 동작을 고정하는 단위 테스트를 역할별로 재배치·보강하며 품질 기준 자체는 변경하지 않는다.
