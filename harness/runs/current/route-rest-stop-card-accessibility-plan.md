# Route Rest Stop Card Accessibility Correction Plan

**Goal:** 상단 경로 선택 카드에 잘못 추가된 이동 화살표를 제거하고, 실제 상세정보로 이동하는 하단 휴게소 결과 카드에 이동 표시와 키보드 접근성을 적용한다.

**Architecture:** 기존 `createRouteResultItem`이 만드는 `li` 카드와 클릭 이벤트 흐름은 유지한다. 카드에 버튼 역할, 포커스 진입, Enter·Space 활성화와 상세 이동 화살표를 추가하며, 상단 경로 선택 카드는 기존 선택 강조와 `aria-pressed`만 유지한다.

**Tech Stack:** JavaScript ES module, CSS, Node test runner

## 작업 목표

- 상세정보로 이동하는 휴게소 결과 카드에만 이동 가능성을 표시한다.
- 마우스·터치뿐 아니라 키보드로도 동일한 상세 진입 동작을 사용할 수 있게 한다.

## 변경 스펙

- 상단 `경로 1·2` 선택 카드에서 이번 작업으로 추가됐던 우측 화살표를 제거한다.
- 하단 경로상 휴게소 결과 카드에는 우측 화살표를 표시한다.
- 휴게소 결과 카드는 기존 마우스·터치 클릭 동작을 유지한다.
- 휴게소 결과 카드는 키보드 포커스가 가능하며 Enter 또는 Space로 상세정보를 연다.
- 포커스 상태는 `focus-visible` 윤곽선으로 표시한다.
- 휴게소 카드의 이미지, 이름, 교통 상태, 배지, 유가 정보 레이아웃은 유지한다.

## 구현 순서

1. 상단 경로 카드에 이동 화살표가 없고 휴게소 결과 카드가 접근 가능한 상세 진입 요소임을 검사하는 실패 테스트를 작성한다.
2. 집중 테스트에서 예상 실패를 확인한다.
3. 상단 경로 카드의 화살표 마크업·스타일을 제거한다.
4. 휴게소 결과 카드에 역할, 레이블, 포커스, 키보드 활성화와 이동 화살표를 추가한다.
5. 집중 테스트와 전체 프론트엔드 테스트를 통과시킨다.
6. 코드·테스트·관련 문서 정합성을 한 번 리뷰하고 하네스 검증 후 커밋한다.

## Trade-off

- `li` 내부를 새로운 `button` 구조로 전면 변경하면 native button 의미를 얻을 수 있지만, 이미지·본문·유가 영역의 grid 구조와 CSS 영향 범위가 커진다.
- 이번 수정은 기존 카드 전체 클릭 구조를 유지하면서 `role="button"`, `tabindex`, Enter·Space 처리를 명시해 변경 범위를 줄인다.
- 상단 경로 카드는 이미 native button이므로 선택 상태를 나타내는 `aria-pressed`와 포커스 표현은 유지하고, 잘못 배치된 시각적 화살표만 제거한다.

## 스펙 영향도

- 스펙 변경 없음 판단 이유: 기존 경로 선택과 휴게소 상세 진입 기능 및 요청·응답 계약은 유지하고, 이동 표시의 위치와 클라이언트 입력 방식만 바로잡기 때문이다.
- 내부 API: 변경 없음.
- 외부 API: 변경 없음.
- 데이터: 변경 없음.
- 제품: 기존 상세 진입 기능의 시각적 위치와 접근성만 바로잡는다.
- 아키텍처: 변경 없음. 기존 렌더링 함수와 상세 선택 흐름을 유지한다.
- 기준 문서: 제품·데이터·API·아키텍처 계약 변화가 없어 동기화할 문서가 없다.
