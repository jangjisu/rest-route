# 관리자 API 39개 — 현재 동작 관찰 기록

**측정일:** 2026-09-10 / 브랜치 `pr/21-e2e-endpoint-coverage` / main `21a6847` 기준

**방법:** 실제 서버 + MySQL 컨테이너 위에서 단언 없이 status와 body만 출력했다. 아래 값은 **설계 의도가 아니라 관찰된 사실**이고, 인수 테스트의 기대값은 전부 여기서 가져온다.

---

## 1. 인가 — 조회와 변경이 갈린다

| 갈래 | 결과 |
| --- | --- |
| 비인증 **조회**(페이지·API 모두) | **302 → `/login`** — API도 JSON 401이 아니다 |
| 비인증 **변경**, CSRF 토큰 없음 | **403** + 스프링 기본 오류 형식(`{"timestamp":…,"error":"Forbidden"}`) |
| 비인증 **변경**, CSRF 토큰 있음 | **302 → `/login`** |
| 인증 후 조회 | 200 (페이지는 `text/html`, API는 `application/json`) |
| 비밀번호 오류 | 302 → `/login?error` |

**CSRF 필터가 인가보다 먼저 돈다.** 토큰 없는 변경 요청의 403은 "권한이 없다"가 아니라 "토큰이 없다"이고, 토큰을 실으면 그제서야 인가 단계로 넘어가 302가 된다. 둘을 짝으로 고정해야 403의 의미가 분명해진다.

## 2. 인증 흐름 — 세션과 토큰이 **함께 회전**한다

```
GET /            →  세션 S1 + 토큰 T1  (meta[name=_csrf])
POST /login      →  302 /admin, 새 세션 S2      ← 세션 고정 공격 방어
GET / (S2)       →  토큰 T2                     ← S2 기준으로 재발급
이후 요청 (S2+T2)
```

로그인 전에 받은 토큰을 그대로 쓰면 403이다. 인수 테스트의 `AdminSessions`가 이 순서를 그대로 밟는다.

**함정 하나:** 로그인 이후의 페이지가 `Set-Cookie`를 내려주지 않을 수 있어서, 응답 쿠키로 세션을 **덮어쓰면** 인증을 잃고 조용히 익명 요청이 된다(오류가 아니라 로그인 페이지 HTML이 200으로 돌아온다). 쿠키는 누적해야 한다.

## 3. 상태 변경 — 동기화 잠금

| 대상 | 잠금 초기값 | 저장 후 | 잠금해제 후 |
| --- | --- | --- | --- |
| 동기화로 들어온 휴게소 | `false` | `true` | `false` (값은 유지) |
| **관리자가 만든 휴게소** | **`true`** | — | — |
| 관리자가 추가한 먹거리 | **`true`** (`adminCreated: true`) | — | `false` (메뉴는 유지) |

`RestStopEntity.createByAdmin`은 처음부터 `adminOverridden=true`다 — 동기화가 만들지 않은 행이라 배치가 건드리면 안 되기 때문이다. **잠금이 풀린 상태가 전제인 시나리오는 동기화 픽스처를 따로 써야 한다.**

## 4. 응답 코드가 갈리는 지점들

| 요청 | 결과 |
| --- | --- |
| 없는 휴게소 편집 조회 | 404 (`Rest stop not found: {코드}`) |
| 없는 휴게소에 **먹거리 추가** | **404** |
| 먹거리 이미지 업로드(PUT) | **204** (200이 아니다) |
| 먹거리 이미지 없음 | 204 / 메뉴 자체가 없음 → 404 |
| 휴일 삭제 | 204 / 없는 휴일 → 404 |
| `GET /api/admin/rest-stops/UNKNOWN/foods` | **200 + 빈 배열** (404가 아니다) |

마지막 줄이 눈에 띈다 — 같은 "없는 휴게소"인데 편집 조회는 404, 먹거리 목록은 200이다.

## 5. 파일 업로드

- **이미지**: JPEG/PNG만 받아 webp로 변환한다(`ImageIO`). 아무 바이트나 보내면 400이고, 그 400은 업로드 경로를 검증한 게 아니라 픽스처가 잘못된 것이다 — 테스트는 실제 PNG를 만들어 보낸다.
- **CSV**: **CP949(MS949)** 로 읽는다. 헤더 이름이 정확해야 하며(예: 화장실 현황은 `노선,시설명,남자_변기수,여자_변기수`) 다르면 400이다.
- 업로드 한 번이 상세용·목록용 **두 벌**을 만든다.

---

## 이 기록이 바로잡은 추측

작업 중 다음 값들을 관찰 없이 짐작해 썼다가 테스트가 빨간불로 바로잡았다.

| 짐작 | 실제 |
| --- | --- |
| 먹거리 이미지 업로드 200 | **204** |
| 없는 휴게소 먹거리 추가 400 | **404** |
| CSV 헤더 `노선명,휴게소명,…` | **`노선,시설명,남자_변기수,여자_변기수`** |
| 이미지에 아무 바이트나 보내도 됨 | JPEG/PNG만 |

## 이 기록의 쓰임

인가 규칙에서 `/api/admin/**`를 빼보면 인수 테스트 **12개**가 빨간불이 된다. `SecurityConfigTest`는 대표 경로 6개만 보므로, 관리자 엔드포인트가 패턴 밖에 새로 생기거나 규칙이 좁아지는 변화를 인수 테스트 쪽이 잡는다.
