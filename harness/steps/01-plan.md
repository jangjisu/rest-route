# 1단계: 계획 생성

목표: 이번 run이 어떤 작업인지, 어디까지 진행할 것인지 정한다.

계획 생성 단계에서는 다음을 확인한다.

- 작업 유형
- 작업 범위
- 브랜치 결정(현재 브랜치 유지 또는 새 브랜치)
- 관련 기준 문서
- 계획 문서

이 단계에서 답해야 하는 질문은 다음과 같다.

- 사용자가 요청한 변경은 무엇인가?
- 이 작업을 현재 브랜치에서 이어갈지, 새 브랜치로 뗄지, 그리고 그 이유는 무엇인가? (열린 PR의 파생 작업이면 현재 브랜치, 무관한 새 작업이거나 이미 머지된 코드에 대한 이슈면 새 브랜치)
- 어떤 규칙 파일을 참고해야 하는가?
- `PRODUCT.md`, `DATA.md`, `ARCHITECTURE.md`, `QUALITY.md` 중 무엇이 영향을 받는가?
- 어떤 파일들이 변경될 것으로 예상되는가?

작업 범위나 브랜치 결정이 불명확하다면, 다음 단계로 넘어가기 전에 사용자 확인이 필요하다.

여러 카테고리(백엔드/프론트엔드 등)가 섞여 있어도 계획 단계에서는 하나의 작업 단위로 다룬다.
카테고리는 이후 커밋을 나누는 데만 사용하고, 카테고리별로 순서를 확인하거나 별도로 진행하지 않는다.

기능의 목적이나 동작이 불명확하면 Superpowers의 brainstorming 방식으로 한 번에 하나씩 질문하고, 설계 승인 전에는 구현하지 않는다.
