# 경로상 휴게소 목록 개선 구현 계획

## 작업 목표

- 경로 선택 카드의 시간·거리와 톨비를 두 줄로 분리한다.
- 휴게소명 옆에 인근 교통상태를 배치하고, 이용 가능 정보는 다음 줄의 칩으로 정리한다.
- 전체·주유 가능·먹거리·테마·이벤트·EV 충전 필터를 제공하고 선택 결과에 맞춰 건수와 목록을 함께 갱신한다.

## 화면 변경 스펙

### 경로 선택 카드

- 기존: `5시간 53분 · 406km · 톨비 20,900원`
- 변경:
  - 첫째 줄: `5시간 53분 · 406km`
  - 둘째 줄: `톨비 20,900원`
- 무료 경로는 둘째 줄에 `무료`로 표시한다.

### 휴게소 카드

- 제목 줄은 `목감(서울)휴게소 · 인근 원활`처럼 휴게소명과 인근 교통상태만 함께 표시한다.
- 다음 줄에는 해당 휴게소가 제공하는 `주유 가능`, `먹거리`, `테마`, `이벤트`, `EV 충전` 정보를 한 줄의 칩 영역으로 표시하며, 좁은 화면에서는 동일 영역 안에서 자연스럽게 줄바꿈한다.
- 기존 추천 태그, 노선, 유가 비교 정보와 상세 화면 이동 동작은 유지한다.

### 필터와 결과 갱신

- 경로상 휴게소 목록 위에 `전체`, `주유 가능`, `먹거리`, `테마`, `이벤트`, `EV 충전` 필터를 표시한다.
- 각 필터에는 현재 선택 경로 기준 건수를 함께 표시한다. 예: `전체 9`, `주유 가능 6`.
- 필터 선택 시 선택 상태를 명확히 표시하고 `aria-pressed`를 함께 갱신한다.
- 모달 제목의 결과 건수와 목록을 선택한 필터 결과로 함께 변경한다.
- 조건에 맞는 휴게소가 없으면 목록 영역에 빈 결과 안내를 표시한다.
- 새로운 경로 검색을 시작할 때는 `전체`로 초기화하고, 한 검색 결과 안에서 경로 1·2를 전환할 때는 선택한 필터를 유지한다.
- 필터는 목록에만 적용하며 지도 위 경로와 휴게소 마커는 전체 경로 맥락을 유지한다.

## 필터 판단 기준

- 전체: 현재 경로의 모든 휴게소.
- 주유 가능: 비교 요약에 휘발유·경유·LPG 중 하나 이상의 유가 정보가 존재하는 휴게소.
- 먹거리: `comparisonSummary.foodMenuCount > 0`인 휴게소.
- 테마: `hasTheme === true`인 휴게소.
- 이벤트: `hasEvent === true`인 휴게소.
- EV 충전: `hasEvCharger === true`인 휴게소.

## 접근 방법과 대안

- 선택: 서버 응답을 변경하지 않고 현재 선택 경로의 `restStops`를 원본으로 유지한 채, 순수 함수로 필터별 건수와 표시 목록을 계산한다.
- 선택 이유: 필요한 판단 필드가 응답에 이미 존재하므로 추가 API 호출 없이 즉시 반응하며, 필터 규칙을 단위 테스트하기 쉽다.
- 경로 카드 선택: 문자열 개행 대신 시간·거리와 톨비를 별도 DOM 요소로 렌더링한다. 화면 폭과 문자열 길이에 관계없이 줄 위치를 보장한다.
- 카드 정보 선택: 교통상태는 제목 의미와 밀접하므로 제목 영역으로 옮기고, 이용 가능 정보는 하나의 칩 컨테이너에서 생성해 흩어진 배지를 정리한다.
- 대안: 필터 클릭마다 서버에 조회를 요청할 수 있으나 데이터가 이미 브라우저에 있고 경로당 목록 크기도 제한적이므로 지연과 API 복잡도만 늘어나 제외한다.
- Trade-off: 필터 상태를 프론트엔드에서 하나 더 관리하지만, 서버 계약을 늘리지 않고 경로 전환 시에도 같은 비교 기준을 유지할 수 있다.

## 변경 파일

- `src/main/resources/templates/index.html`
  - 전국 평균 유가와 목록 사이에 필터 컨테이너를 추가한다.
- `src/main/resources/static/js/rest-stops-map.js`
  - 경로 카드의 시간·거리와 톨비를 분리해 렌더링한다.
  - 필터 상태, 분류·건수 계산, 필터 버튼과 빈 결과 렌더링을 추가한다.
  - 휴게소 카드 제목에 교통상태를 배치하고 이용 가능 정보 칩을 한 영역에서 렌더링한다.
- `src/main/resources/static/css/style.css`
  - 경로 카드 둘째 줄, 필터 칩, 제목 옆 교통상태와 이용 가능 칩 행을 반응형으로 정리한다.
- `src/test/js/rest-stops-map.test.js`
  - 경로 요약 분리, 필터 분류·건수, 이용 가능 칩 판단을 검증한다.
- `src/test/js/index-template.test.js`
  - 필터 컨테이너가 경로 결과 모달에 존재하는지 검증한다.

## 스펙 영향도 (Spec Impact)

- 내부 API: 변경 없음. 판단 이유 — 기존 경로 응답의 요약, 유가, 먹거리 건수, 테마·이벤트·EV 여부를 그대로 사용하고 화면에서만 분류한다.
- 외부 API: 변경 없음. 판단 이유 — 외부 API 요청·응답 및 클라이언트를 변경하지 않는다.
- 데이터: 변경 없음. 판단 이유 — 저장 구조와 연결 키를 변경하지 않는다.
- 제품: 기존 경로상 휴게소 비교 기능 안에서 정보 탐색성과 가독성을 개선하며 제품 범위는 변경하지 않는다.
- 아키텍처: 변경 없음. 판단 이유 — 기존 프론트엔드 렌더링 책임 안에서 순수 필터 함수와 UI 상태만 추가한다.
- 품질: 필터 분류와 표시 규칙을 JS 단위 테스트로 고정하고 템플릿 및 전체 회귀 검증을 수행한다.
