# 경로상 휴게소 필터 스크롤바 숨김 계획

## 목표

- 경로상 휴게소 필터의 가로 스크롤 동작은 유지한다.
- Chrome·Safari·Firefox에서 스크롤바 표시만 숨긴다.
- 모달의 세로 스크롤과 다른 스크롤 영역에는 영향을 주지 않는다.

## 구현

- `.route-rest-stop-filters`에 Firefox용 `scrollbar-width: none`과 레거시 Edge용 `-ms-overflow-style: none`을 적용한다.
- `.route-rest-stop-filters::-webkit-scrollbar`만 숨겨 WebKit 계열 브라우저에 적용한다.
- CSS 파일을 읽는 회귀 테스트로 대상 선택자와 속성을 검증한다.

## 접근 방법과 Trade-off

- 선택: 필터 컨테이너의 `overflow-x: auto`는 유지하고 브라우저별 스크롤바 표시 속성만 대상 선택자에 한정해 적용한다.
- 선택 이유: 스크롤 자체를 막거나 필터를 여러 줄로 배치하면 좁은 화면에서 뒤쪽 필터에 접근하기 어렵다. 표시만 숨기면 터치·트랙패드 탐색을 유지하면서 시각적 노이즈를 제거할 수 있다.
- Trade-off: 스크롤 가능 여부를 스크롤바로 알아차리기 어려워지지만, 다음 필터가 화면 가장자리에서 일부 보이고 칩이 한 줄로 이어지는 기존 배치를 유지해 가로 탐색 가능성을 전달한다.

## 스펙 영향도

- 스펙 변경 없음 판단 이유: 기존 필터의 데이터와 동작은 그대로 유지하고 CSS로 스크롤바 표시만 조정하기 때문이다.
- 내부 API: 변경 없음. 요청·응답과 서버 동작을 수정하지 않는다.
- 외부 API: 변경 없음. 외부 연동을 수정하지 않는다.
- 데이터: 변경 없음. 저장 구조나 상태를 추가하지 않는다.
- 제품: 변경 없음. 기존 필터 기능의 시각적 표현만 조정한다.
- 아키텍처: 변경 없음. 기존 CSS 선택자 안에서 표시 방식만 바꾼다.
- 품질: 스크롤 동작을 유지하는 `overflow-x: auto`와 스크롤바 숨김 속성을 회귀 테스트로 함께 확인한다.
