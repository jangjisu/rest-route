# 도메인 문서

엔지니어링 스킬들이 코드베이스를 탐색할 때 이 리포의 도메인 문서를 어떻게 참고해야 하는지 정리한다.

이 리포는 두 개의 서로 다른, 상호보완적인 문서 시스템을 쓴다 — 둘 다 읽는다.

## 탐색 전에 읽을 것

- **루트 `CONTEXT.md`**: 프로젝트 전용 **용어집**. "휴게소", "서비스지역코드", "관리자 재정의", "백필" 같은 이 프로젝트에서만 쓰이는 용어의 정의와, 피해야 할 동의어를 담는다. 도메인 개념을 이름 붙일 때(이슈 제목, 리팩터 제안, 테스트명 등) 여기 정의된 용어를 그대로 쓴다.
- **`docs/domain/<name>.md`**(또는 200줄을 넘겨 분할된 `docs/domain/<domain>/`): 실제로 살아있는 **도메인 위키**. 흐름·정책·상태·권한·오류·데이터 수명주기·API 계약처럼 `CONTEXT.md`의 용어집보다 훨씬 자세한, "지금 이 도메인이 실제로 어떻게 동작하는가"를 담는다. `jisu-dev:domain-wiki` 스킬이 코드 변경 시점마다 갱신하는 대상이라, 이 리포의 도메인 문서 중 가장 최신이고 정확하다.
- **`docs/adr/`**: 이 리포는 아직 ADR을 안 쓴다 — 존재하지 않으면 조용히 넘어간다. 앞으로 생기면 여기에 쌓인다(단일 컨텍스트라 `src/<context>/docs/adr/`는 해당 없음).

파일이 없으면 **조용히 넘어간다**. 없다고 지적하거나 미리 만들자고 제안하지 않는다.

## 파일 구조

단일 컨텍스트 리포(이 리포):

```
/
├── CONTEXT.md              ← 용어집
├── docs/
│   ├── adr/                ← 아직 안 씀
│   └── domain/              ← 실제 도메인 위키(도메인별 파일, 200줄 넘으면 하위 그룹으로 분할)
│       ├── rest-stop.md
│       ├── route.md
│       ├── ev-charger.md
│       └── finder.md
└── src/
```

## 용어집의 어휘를 쓴다

산출물에서 도메인 개념을 이름 붙일 때(이슈 제목, 리팩터 제안, 가설, 테스트명 등) `CONTEXT.md`에 정의된 용어를 그대로 쓴다. 용어집이 명시적으로 피하라고 한 동의어로 흘러가지 않는다.

필요한 개념이 아직 용어집에 없다면 그건 신호다 — 이 프로젝트가 안 쓰는 말을 지어내고 있는 건 아닌지 다시 생각해보거나, 진짜 빠진 부분이면 기록해둔다. 다만 여기서 별도 절차를 새로 만들기보다는 `jisu-dev:domain-wiki`의 조회/갱신 절차를 따라 `docs/domain/*.md`를 직접 갱신하는 쪽을 우선한다.

## ADR 충돌 표시

산출물이 기존 ADR과 모순되면 조용히 덮어쓰지 않고 명시적으로 드러낸다. 이 리포는 아직 ADR이 없어서, 첫 ADR이 생기기 전까지 이 절은 쉬고 있다.
